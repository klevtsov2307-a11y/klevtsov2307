# ЮKassa: тестовый режим

В Netlify Functions / Production должны быть сохранены TELEGRAM_BOT_TOKEN, YOOKASSA_SHOP_ID, YOOKASSA_SECRET_KEY. Секретный ключ принимается только с префиксом test_; реальные ключи не допускаются этой интеграцией. После изменения переменных нужен новый deploy.

В Telegram: Настройки → Подписка → ввести партнёрский код (необязательно) → Создать тестовый платёж → открыть платёжную страницу. Сервер сам определяет цену: 800 RUB по существующему коду, иначе 2667 RUB. На странице ЮKassa использовать тестовый способ оплаты/тестовую карту из документации ЮKassa, не настоящую карту. После оплаты вернуться в Mini App и нажать «Проверить тестовый платёж». Возврат на сайт сам по себе не подтверждает платёж.

Сервер проверяет Telegram HMAC, владельца заказа и подтверждённые API ЮKassa test, paid/status, сумму, валюту и metadata. Повторное создание с тем же requestId использует один idempotency key. Партнёр к заказу привязывается только серверной проверкой кода. Ключи и банковские реквизиты клиенту не передаются.

Это разовый тест, не подписка. Реальные деньги, доступ, баланс партнёра и выплаты не изменяются. Webhook и автоматическое продление не подключены. Цифровые продажи внутри Telegram должны отдельно учитывать обязательные требования Stars; тестовая интеграция не решает этот вопрос.

Внешний браузер без подтверждённого Telegram initData не может создавать или проверять заказ. Для веб-версии позднее нужен самостоятельный проверенный вход. Функции работают на Netlify, локальный npm start обслуживает только статику.
